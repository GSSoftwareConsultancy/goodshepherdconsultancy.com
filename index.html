Company

One company, two kinds of work.

Good Shepherd Software Consultancy was incorporated in 2015 to do senior engineering for organisations that needed it done properly: cloud data platforms, Java and Python systems, and the migration of legacy estates onto them. That work continues.

Since 2025 the company has also built software of its own, published under the EnrichMeAI trading name. All of it is open source, Apache 2.0 licensed, and self-hostable. Its subject is accountability for work done by AI agents: on the data side, agents ask before they read; on the agent side, what an agent did is written down. Nothing there is announced before it runs.

What we build · as EnrichMeAI

Water infrastructure, for data.

Three projects, named for the things that store, gate and carry water. Each stands on its own; together they are one practice, held to one rule: nothing ships until it has run on real infrastructure.

  • Cistern the gateway between AI agents and your data

    Stands in front of what is yours and makes every application and AI assistant ask permission instead of taking copies. The owner writes the rule, Cistern enforces it on every request, revokes it on the next, and leaves a receipt of every allow and deny. Built on open specifications, in the open.

    Java · Spring BootApache 2.0enrichmeai.com/cistern ↗Source ↗

  • Penstock the agent that keeps a record

    A self-hosted agent for the workflows an editor cannot reach, and the reference client for governed, receipted access to your own data. Every model call and every tool invocation is written to an audit log the owner reads back.

    Java · Spring BootApache 2.0enrichmeai.com/penstock ↗Source ↗

  • Culvert a data-pipeline framework with no AI in it

    Pipelines defined once against a language-neutral contract set, then run on any cloud by swapping adapters instead of rewriting logic. Published on PyPI and Maven Central after a real deployment, not before. It is where the practice the other two are held to was proven.

    Java · PythonApache 2.0enrichmeai.com/culvert ↗Source ↗

Engagements

Senior engineering, done by the people you spoke to.

We take a small number of engagements at a time and do the work ourselves. The pattern is the same whether the client is a bank, an enterprise, or a company of four: understand the constraint, build the thing, run it on the real infrastructure, and leave the client able to run it without us.

  • Cloud data platformsDesign and delivery on Google Cloud: ingestion, pipelines, governance, and the operating model around them.
  • Legacy migrationMainframe and legacy data estates moved onto the cloud with a metadata-driven, resilient method, not a big-bang cutover.
  • Java and Python systemsServices, frameworks and the plumbing between them. Spring, reactive, event-driven, tested against contracts.
  • AI in the engineering loopWe use AI heavily in our own work, held to the same contracts and gates as any other contributor, and we can set that up for yours.

How we work, everywhere: tests earn a deployment, and a deployment earns a release. What worked and what did not goes in the release notes, where it can be checked.
